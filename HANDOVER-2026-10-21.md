## 1. The project in one paragraph

Cozy Acres is a mobile-first 3D farming and village builder that runs in the browser and installs as an offline PWA
(Three.js + TypeScript + Vite, about 43,000 lines of TypeScript in 228 source files, 42 JSON data files). Optional online
play (friends, gifts, market, leaderboards, farm visits, Ask a friend, co-op Village Projects, cloud saves) runs on
Supabase. An Android Trusted Web Activity wraps the live site and is in Google Play closed testing; web deploys reach it
without a new build. Owner: Josh Makes Games. Repo `JLA92-bit/Cozy-Farm`, work on `main`; pushing deploys through GitHub
Pages. Game: https://cozyacres.joshmakesgames.app/play/ . Admin dashboard: `/admin/` (`ADMIN.md`).

## 4. What is risky or untested

1. **Nothing since about 1.18 has been tested on a real phone.** Everything was checked in headless Chromium with
   SwiftShader. Priority: play through on the owner's Pixel on Low, Medium and High (rule 9), especially the woods,
   the square (Clock Tower, Lighthouse), Village Projects, the lock screen in landscape and portrait.
2. **The regression tests drive the game through code, not real taps.** That is how the Halloween vignette slipped
   through. One check now looks for anything covering the farm; any new full-screen element needs a real input test.
3. **Supabase must be re-run after server changes.** If the owner reports "Could not find the function ... in the
   schema cache", the latest `schema.sql` has not run all the way through (or `notify pgrst, 'reload schema';` was
   missed). The SQL Editor stops at the first error, so ask for the red error text.
4. **Admin pages were checked with mock data only** (Playwright screenshots of `admin/` with a stubbed `../api`). Real
   data may show edge cases (players without a save, very old saves, missing fields).
5. **Open items from CLAUDE.md section 8** still stand: redeploy `send-push` with `PUSH_CRON_SECRET`, recruit closed
   testers, the Android workflow deprecations (Ubuntu 26 from 19 October), production application after the 14-day test.

## 5. How work has been done (keep doing this)

- Plan, build, then verify: `npx tsc --noEmit`, `npm run validate-data`, `npm run test:regression`, `npm run test:perf`
  for anything visual, `bash scripts/pages/build.sh` before a push.
- Server work is tested on a local Postgres 16 with a stub `auth` schema before the owner runs it. Re-create it if the
  container is new: install PostgreSQL 16, create a user, a database `cozy`, roles `anon`/`authenticated`/`service_role`
  and a minimal `auth` schema (`auth.users`, `auth.identities`, `auth.uid()` from `request.jwt.claim.sub`, `auth.jwt()`
  from `request.jwt.claims`), then run `schema.sql` twice to prove it is re-runnable.
- Screenshots of new screens (game and dashboard) are taken with Playwright and the pre-installed Chromium and shown to
  the owner before pushing.
- **Never push without the owner's "yes push"** (rule 12). Commit locally, say in two lines what goes live, wait. The
  automated "unpushed commits" reminder is not permission. After a push, remind the owner to run `schema.sql` when the
  server changed.
- Owner preferences: plain words, no em dashes anywhere (use a hyphen), short summaries of what changed and what to do.
